# Long-Lived Agent Sessions with Pi's Session Manager

## Goal

Replace the current per-request agent creation + manual DB history reconstruction with **long-lived Pi agents per chat session** backed by Pi's file-based `SessionManager`. This gives us:

- **Automatic compaction** — Pi triggers compaction when context exceeds threshold (`agent-session.js:1441-1461`, `_checkCompaction`)
- **No manual history replay** — Pi's `SessionManager` loads/saves session entries from JSONL files (`session-manager.js:244-289`, `setSessionFile`)
- **No format fragility** — eliminates `message-replay.ts` and its requirement for byte-identical output to Pi's internal wire format

## Problem with Current Approach

**`src/lib/pi/session.ts:179`** — `createPiSession` uses `SessionManager.inMemory()`:
```ts
const result = await createAgentSession({
    sessionManager: SessionManager.inMemory(),
    // ...
});
```

**`src/app/api/chat/sessions/[sessionId]/stream/route.ts:314-317`** — History is manually reconstructed from DB and injected:
```ts
piSession.agent.state.messages = historyMessages as any;
```

This bypasses Pi's session system entirely. Pi's auto-compaction (`agent-session.js:1394-1461`, `_checkCompaction`) checks `agent.state.messages` usage tokens after each turn — but since we create a fresh agent per request with manually injected messages, Pi has no persistent context tracking and compaction never triggers.

## Architecture

### Session File Storage

Each chat session gets a Pi JSONL session file stored under the persistent uploads volume:

```
UPLOADS_DIR/pi_sessions/{userId}/{chatSessionId}/
  └── {timestamp}_{sessionId}.jsonl   (e.g. 2025-06-08T14-30-00-000Z_abc123.jsonl)
```

- `UPLOADS_DIR` is `/app/uploads` in docker, mounted as `uploads_data` volume (`docker-compose.yml:14`)
- Survives process restarts (persistent volume)
- Isolated per user (userId in path), one directory per chat session
- Each directory has exactly one JSONL file — Pi never creates multiple files per session (no branching in chat usage)
- File name is generated by `newSession()` (`session-manager.js:567`): `{timestamp}_{sessionId}.jsonl`
- Entries are written append-only via `_persist()` (`session-manager.js:355-376`, `appendFileSync`)
- First write is deferred until the first assistant message (`_persist` checks `hasAssistant` flag)

### Recovery After Restart

`SessionManager.continueRecent()` (`session-manager.js:1094-1102`) handles recovery:

1. Calls `findMostRecentSession(dir)` (`session-manager.js:523-540`) — scans directory for `.jsonl` files
2. Reads session header from first 512 bytes of each file (`readSessionHeader`, `session-manager.js:293-310`)
3. Returns the most recently modified file path
4. Constructor calls `setSessionFile(filePath)` (`session-manager.js:522-523`)
5. `setSessionFile` calls `loadEntriesFromFile(filePath)` (`session-manager.js:199-235`) — parses all JSONL lines, runs migrations
6. `_buildIndex()` (`session-manager.js:592-609`) — builds `byId` map, sets `leafId` to last entry
7. `buildSessionContext()` (`session-manager.js:105-189`) — walks tree from leaf to root, handles compaction entries, returns resolved message list

**If compaction occurred before restart:**
- The compaction entry (`{ type: "compaction", summary, firstKeptEntryId, ... }`) is in the JSONL file
- `buildSessionContext()` finds it in the path and:
  - Emits `createCompactionSummaryMessage(summary)` as the first message (`messages.js:48-53`)
  - Skips entries before `firstKeptEntryId`
  - Includes entries from `firstKeptEntryId` through the compaction
  - Includes entries after the compaction
- The agent's `state.messages` is correctly reconstructed with the summary + kept messages

**If no file exists (first use or directory deleted):**
- `findMostRecentSession` returns `null`
- `continueRecent` falls through to `new SessionManager(cwd, dir, undefined, true)` → `newSession()` → creates fresh header

### Why Not `SessionManager.create()`?

`SessionManager.create()` (`session-manager.js:1069-1072`) passes `sessionFile = undefined` to the constructor, which calls `newSession()` — always creating a new session header and new file path. On restart this would:
- Create a new JSONL file (orphaning the old one with all the history)
- Lose all context (no messages loaded)
- Lose all compaction state

`continueRecent()` is the correct choice — it finds and loads existing files.

### Double-Prompting Prevention

The key problem: GET `/stream` may be called multiple times (initial connect, reconnect after refresh). We must only call `session.prompt()` once per user message.

**Guard:** `lastPromptedMessageId` on the pooled session.

```ts
// In GET /stream handler:
const latestUserMessage = /* last user message from DB */;
const pooled = agentPool.get(poolKey);

if (pooled) {
  if (pooled.lastPromptedMessageId === latestUserMessage.id) {
    // Already processed — just subscribe to Redis pub/sub (reconnect path)
    return handleReconnect(sessionId);
  }
  // New message not yet processed — prompt
  pooled.session.prompt(latestUserMessage.content, images);
  pooled.lastPromptedMessageId = latestUserMessage.id;
} else {
  // First time — create agent, prompt
  const newSession = await createAgentWithSessionDir(userId, sessionId, sessionDir);
  agentPool.set(poolKey, {
    session: newSession.session,
    sessionDir,
    lastPromptedMessageId: latestUserMessage.id,
    lastActive: Date.now(),
  });
  newSession.session.prompt(latestUserMessage.content, images);
}
```

### Process Restart Behavior

1. Process restarts → `agentPool` is empty (in-memory)
2. User sends a new message → POST saves to DB, sets `processingSince`
3. Client connects GET `/stream` → agent not in pool
4. `SessionManager.create(sessionDir)` loads existing JSONL file from disk (`session-manager.js:247-272`, `setSessionFile` → `loadEntriesFromFile`)
5. Pi reconstructs full context from file entries (`session-manager.js:105-189`, `buildSessionContext`)
6. If compaction occurred previously, Pi includes the compaction summary message (`messages.js:48-53`, `createCompactionSummaryMessage`) and only messages after `firstKeptEntryId`
7. Agent prompts with the new user message — context is correct

**No data loss.** The JSONL file on disk is the source of truth. The pool is just a cache of live agent instances.

### Idle Eviction

```ts
const MAX_IDLE_MS = 30 * 60 * 1000;  // 30 minutes
const MAX_POOL_SIZE = 100;            // per process

function evictIdle() {
  const now = Date.now();
  for (const [key, entry] of agentPool) {
    if (now - entry.lastActive > MAX_IDLE_MS && !entry.session.isStreaming) {
      entry.session.dispose();  // agent-session.d.ts:218
      agentPool.delete(key);
      // Session file on disk is preserved — agent can be recreated later
    }
  }
  // Hard cap — evict oldest idle sessions
  while (agentPool.size > MAX_POOL_SIZE) {
    const oldest = [...agentPool.entries()].sort((a, b) => a[1].lastActive - b[1].lastActive)[0];
    if (oldest) {
      oldest[1].session.dispose();
      agentPool.delete(oldest[0]);
    }
  }
}

// Run every 5 minutes
const evictionTimer = setInterval(evictIdle, 5 * 60 * 1000);
```

### `src/lib/pi/agent-pool.ts` (NEW)

Agent pool with lifecycle management.

```ts
import type { AgentSession } from "@earendil-works/pi-coding-agent";

interface PooledSession {
  session: AgentSession;
  sessionDir: string;
  lastPromptedMessageId: string | null;  // ChatMessage.id from DB
  lastActive: number;
}

const pool = new Map<string, PooledSession>();
const MAX_IDLE_MS = 30 * 60 * 1000;
const MAX_POOL_SIZE = 100;

export function getPoolKey(userId: string, sessionId: string): string {
  return `${userId}:${sessionId}`;
}

export function getSessionDir(userId: string, sessionId: string): string {
  // UPLOADS_DIR/pi_sessions/{userId}/{sessionId}/
  // Must be absolute path — SessionManager.create() passes it through mkdirSync
  const uploadsDir = process.env.UPLOADS_DIR ?? "./uploads";
  return path.join(uploadsDir, "pi_sessions", userId, sessionId);
}

export function getOrCreate(
  key: string,
  createFn: () => Promise<{ session: AgentSession; sessionDir: string }>,
): PooledSession {
  const existing = pool.get(key);
  if (existing) {
    existing.lastActive = Date.now();
    return existing;
  }
  // Eviction runs before creating new entries
  evictIdle();
  throw new Error("Agent not in pool — caller must create via createAndPool()");
}

export async function createAndPool(
  key: string,
  createFn: () => Promise<{ session: AgentSession; sessionDir: string }>,
): Promise<PooledSession> {
  const existing = pool.get(key);
  if (existing) {
    existing.lastActive = Date.now();
    return existing;
  }
  evictIdle();
  const { session, sessionDir } = await createFn();
  const entry: PooledSession = {
    session,
    sessionDir,
    lastPromptedMessageId: null,
    lastActive: Date.now(),
  };
  pool.set(key, entry);
  return entry;
}

export function remove(key: string): void {
  const entry = pool.get(key);
  if (entry) {
    entry.session.dispose();  // agent-session.d.ts:218 — removes listeners, disconnects
    // Session file on disk is preserved — can be reloaded later
    pool.delete(key);
  }
}

export function get(key: string): PooledSession | undefined {
  const entry = pool.get(key);
  if (entry) {
    entry.lastActive = Date.now();
  }
  return entry;
}

export function evictIdle(): void {
  const now = Date.now();
  for (const [key, entry] of pool) {
    if (now - entry.lastActive > MAX_IDLE_MS && !entry.session.isStreaming) {
      entry.session.dispose();
      pool.delete(key);
    }
  }
  while (pool.size > MAX_POOL_SIZE) {
    const sorted = [...pool.entries()].sort((a, b) => a[1].lastActive - b[1].lastActive);
    const [oldestKey] = sorted[0];
    if (oldestKey && pool.has(oldestKey)) {
      pool.get(oldestKey)!.session.dispose();
      pool.delete(oldestKey);
    }
  }
}

// Periodic eviction
const timer = setInterval(evictIdle, 5 * 60 * 1000);
timer.unref(); // Don't keep process alive

export function shutdown(): void {
  clearInterval(timer);
  for (const [, entry] of pool) {
    entry.session.dispose();
  }
  pool.clear();
}
```

### `src/lib/pi/persistent-session.ts` (NEW)

Factory for creating Pi sessions with file-based `SessionManager`. Replaces the session creation logic in `stream/route.ts`.

```ts
import path from "path";
import fs from "fs/promises";
import {
  createAgentSession,
  SessionManager,
  type CreateAgentSessionResult,
  type ToolDefinition,
} from "@earendil-works/pi-coding-agent";
// ... imports from existing session.ts

/**
 * Create a Pi agent session with file-based persistence.
 *
 * Uses SessionManager.create() (session-manager.js:static create()) which:
 * - Creates sessionDir if it doesn't exist
 * - Generates a JSONL file path: {sessionDir}/{timestamp}_{sessionId}.jsonl
 * - Passes persist=true to the SessionManager constructor
 * - On subsequent calls with same sessionDir, existing entries are loaded from disk
 *
 * The session file survives process restarts (stored on uploads_data volume).
 */
export async function createPersistentSession(options: {
  userId: string;
  sessionId: string;       // ChatSession.id from DB
  sessionDir: string;      // pi_sessions/{userId}/{sessionId}/
  customTools: ToolDefinition[];
  toolConfig?: ToolConfig;
  modelProvider?: string;
  modelName?: string;
  thinkingLevel?: string;
}): Promise<CreateAgentSessionResult> {
  // Ensure session directory exists
  await fs.mkdir(options.sessionDir, { recursive: true });

  // Build model registry (same as current createPiSession)
  const { modelRegistry, authStorage } = await buildModelRegistry(options.userId);

  // Resolve tools (same as current)
  const enabled = resolveToolConfig(options.toolConfig);
  const allCustomTools: ToolDefinition[] = [...options.customTools];
  const resolvedTools = resolveTools(options.userId, options.sessionId, enabled, {
    createLocalScopedTools,
    createTerminalScopedTools,
  });
  allCustomTools.push(...resolvedTools);

  // Resolve model
  let model;
  if (options.modelProvider && options.modelName) {
    model = modelRegistry.find(options.modelProvider, options.modelName);
  }

  // Create or resume file-based SessionManager.
  //
  // SessionManager.create() ALWAYS creates a new session (new header, new file path).
  // It does NOT look for existing files. Using it on restart would orphan the old
  // session file and lose all context.
  //
  // SessionManager.continueRecent() (session-manager.js:1094-1102):
  //   1. Calls findMostRecentSession() to scan sessionDir for .jsonl files
  //   2. If found → new SessionManager(cwd, dir, filePath, true) → setSessionFile()
  //      → loadEntriesFromFile() → builds full in-memory index from disk
  //   3. If not found → new SessionManager(cwd, dir, undefined, true) → newSession()
  //      → creates fresh session header and generates new file path
  //
  // Since each chat session has its own directory (pi_sessions/{userId}/{id}/)
  // with exactly one JSONL file, continueRecent() always finds the right file.
  const sessionManager = SessionManager.continueRecent(
    options.sessionDir,  // cwd — stored in session header
    options.sessionDir,  // sessionDir — where JSONL files are written
  );

  const result = await createAgentSession({
    sessionManager,           // File-based — entries persist to JSONL
    authStorage,
    modelRegistry,
    noTools: "builtin",
    ...(model ? { model } : {}),
    customTools: allCustomTools,
    thinkingLevel:
      (options.thinkingLevel as "off" | "minimal" | "low" | "medium" | "high" | "xhigh") ?? "off",
  });

  return result;
}
```

## Risks and Mitigations

| Risk | Mitigation |
|------|-----------|
| **Memory growth** — each active agent holds ~50-200MB | Idle eviction (30min), hard cap (100 sessions), `dispose()` on removal |
| **Session file grows unbounded** | Pi's compaction reduces in-memory context. JSONL file keeps full history — consider adding a file size cap or periodic archival. |
| **Disk space** — JSONL files accumulate | Session DELETE already cleans up files. Add a cron job to clean orphaned dirs. |
| **Process restart loses active agents** | Session files on disk survive. Next request recreates agent from file. User may need to re-send their last message if it was in-flight. |
| **Multiple instances** — pool is per-process | Current docker compose is single-instance. For multi-instance: need sticky sessions or a shared agent process (worker model). |
| **Pi API changes** — SessionManager internals | We only use public APIs: `SessionManager.create()`, `createAgentSession()`, `session.prompt()`, `session.subscribe()`, `session.abort()`, `session.dispose()`. These are stable SDK entry points. |
| **Tool config changes mid-session** | Tools are set at agent creation time. Model/tool changes via PATCH endpoint won't take effect until the agent is evicted and recreated. Acceptable for now. |

## What Doesn't Change

- **DB schema** — no migrations needed (session files are on disk, not in DB)

- **Rate limiting** — unchanged
- **Auth** — unchanged
