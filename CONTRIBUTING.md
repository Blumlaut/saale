# Contributing

Saale is a small project with one maintainer, so a little talking first goes a long way.

## Before you build something

For a bug fix or a small change, go ahead and open the pull request.

For something larger, such as a new module, a schema change or a new dependency, open an
issue first and describe what you want to do and why. We can settle whether it fits and
how it should look before you spend a weekend on it.

## Generative AI

Using an assistant is fine, and a pull request is not handled any differently because of
it. Say in the description that you used one, and name the model if you can.

## What merging means

A merged contribution becomes part of Saale under the project's licence, and you waive any
claim of ownership over it.

## The usual

- Write in English.
- One pull request, one change.
- Run `npm run check` before you push. It lints, type-checks, checks formatting and runs
  the tests.
- Come back with a question instead of a guess, and assume the other person is arguing in
  good faith.

## Security

Do not open a public issue for a security problem. [SECURITY.md](.github/SECURITY.md) says
where to send it.
